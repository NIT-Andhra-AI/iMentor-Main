## 1. Course Overview & Pedagogical Framework

### 1.1 Course Syllabus & Description
**Course Code:** EE3031  
**Course Title:** Embedded Systems Architecture & Real-Time Design  
**Credits:** 4 (3 Lectures + 1 Practical/Lab Session per week)  
**Target Audience:** Undergraduate Electrical Engineering & Computer Engineering Students  

EE3031 offers an in-depth treatment of modern embedded system design, bridging hardware architecture, low-level software engineering, real-time operating systems (RTOS), and peripheral interfacing. Using the 32-bit ARM Cortex-M4 microcontroller as the primary target platform, the course guides students through assembly and register-level C programming, real-time task scheduling, hardware interrupt handling, low-power optimization, and bus protocols.

### Module 1: Embedded Software Development & Lifecycle Models (Lectures 1–6)

#### Lecture 1: Introduction to Embedded Systems & Microprocessor vs Microcontroller Architecture
- **Learning Objectives:** Differentiate between MPU and MCU architectures; analyze Harvard vs Von Neumann memory topologies.
- **Topics Covered:** MPU vs MCU comparisons, integrated peripherals, system buses, on-chip vs external RAM/Flash.
- **Board/Slide Notes:** Diagram Harvard (separate I-Bus, D-Bus) vs Von Neumann (shared bus). Highlight bus contention.
- **Key Equations:** $\text{System Throughput} = \frac{\text{Instructions Executed}}{\text{Total Clock Cycles} \times T_{\text{clk}}}$.
- **In-Class Activity:** Hand out STM32F4 block diagram; ask students to identify Flash, SRAM, Core, and AHB/APB bus bridges.

#### Lecture 2: Embedded System Design Metrics & Trade-offs
- **Learning Objectives:** Formulate mathematical trade-offs between NRE cost, unit cost, latency, throughput, and time-to-market.
- **Topics Covered:** NRE cost amortization, revenue loss model for TTM delays, dynamic power equation $P = \alpha C V^2 f$.
- **Board/Slide Notes:** Derivation of unit cost vs production volume curve. Revenue loss percentage formula.
- **Key Equations:** $\text{Cost}_{\text{unit\_total}} = \frac{\text{NRE}}{N} + \text{Unit Cost}$; $\text{Revenue Loss \%} = \frac{D(3W-D)}{2W^2} \times 100\%$.
- **In-Class Activity:** Solve a numerical where a 3-month TTM delay cuts market revenue by 28%.

#### Lecture 3: Software Lifecycle Models: Waterfall vs V-Model
- **Learning Objectives:** Critique Waterfall and V-Model paradigms in safety-critical embedded engineering.
- **Topics Covered:** Hardware-software co-design iterations, V-Model verification phases (Unit, Integration, System, Acceptance testing).
- **Board/Slide Notes:** Draw V-Model showing horizontal mapping between left-side specifications and right-side test validation.
- **Key Equations:** N/A (Methodological).
- **In-Class Activity:** Group discussion on ISO 26262 automotive safety requirements and V-Model compliance.

#### Lecture 4: Concurrency & Foreground/Background Execution Architectures
- **Learning Objectives:** Analyze non-preemptive foreground/background (ISR + main loop) architectures vs sequential loops.
- **Topics Covered:** Interrupt flags, volatile global variables, latency sources in polling loops.
- **Board/Slide Notes:** Flowchart of main loop checking `flag_adc_complete` set asynchronously by ADC ISR.
- **Key Equations:** $\text{Max Polling Latency} = \text{WCET of Background Loop}$.
- **In-Class Activity:** Trace a C code snippet containing a subtle race condition caused by missing `volatile` qualifier.

#### Lecture 5: Real-Time Scheduling Theory: Rate Monotonic Scheduling (RMS)
- **Learning Objectives:** Prove and evaluate schedulability of periodic task sets under Rate Monotonic Scheduling.
- **Topics Covered:** Fixed priority assignment based on task period, Liu & Layland utilization bound derivation.
- **Board/Slide Notes:** Plot CPU execution timelines for 2 tasks. Derive $U(n) = n(2^{1/n}-1)$ limit as $n \to \infty$ ($0.693$).
- **Key Equations:** $U = \sum_{i=1}^n \frac{C_i}{T_i} \le n(2^{1/n}-1)$.
- **In-Class Activity:** Solve RMS schedulability for a 3-task set with $U = 0.72$.

#### Lecture 6: Earliest Deadline First (EDF) & Software Unit Testing
- **Learning Objectives:** Compare EDF dynamic scheduling with RMS; apply Equivalence Partitioning and Cyclomatic Complexity to embedded C code.
- **Topics Covered:** Dynamic priority assignment, $U \le 1.0$ bound for EDF, Boundary Value Analysis (BVA), $V(G) = E - N + 2P$.
- **Board/Slide Notes:** Draw control flow graph of an IF-ELSE block. Calculate $V(G) = 3$.
- **Key Equations:** $V(G) = E - N + 2P = D + 1$.
- **In-Class Activity:** Design a host C test bench mocking STM32 GPIO registers for unit testing LED drivers.

## 4. Common Student Misconceptions & Pedagogical Remediation

### 4.1 Misconception 1: Bit-Banding Shift vs Alias Offset Multiplication
- **Student Error:** Students frequently write $\text{Alias Address} = \text{Alias Base} + (\text{Byte Offset} \times 8) + \text{Bit}$, confusing bit-band alias expansion with simple bit shifting.
- **Root Cause:** Inability to grasp that each single bit in the target region expands to a full 32-bit (4-byte) word in alias space.
- **Remediation Strategy:** Show students the memory expansion geometry. A byte contains 8 bits, requiring $8 \times 4 = 32 \text{ bytes}$ of alias memory space. Hence, multiply byte offset by 32 (or left-shift by 5), and multiply bit position by 4 (left-shift by 2).

### 4.2 Misconception 2: Hardware Exception Stacking vs Standard Function Calls
- **Student Error:** Expecting that calling an ISR requires explicit register pushing in assembly (`PUSH {R0-R3}`) like C functions.
- **Root Cause:** Transposing standard AAPCS function calling conventions directly to hardware exceptions.
- **Remediation Strategy:** Emphasize that the Cortex-M4 **NVIC hardware automatically pushes R0-R3, R12, LR, PC, and xPSR** onto the stack in 12 clock cycles *before* executing the first line of ISR assembly code.

### 4.3 Misconception 3: Omitting the `volatile` Keyword in Embedded C
- **Student Error:** Writing `while(!flag);` where `flag` is updated inside an ISR, leading to infinite loops when compiler optimization (`-O2` or `-O3`) is enabled.
- **Root Cause:** Ignorance of compiler optimizations that cache hardware register/variable values in CPU core registers (e.g., R0) when no internal loop mutation is visible.
- **Remediation Strategy:** Demonstrate disassembly of compiled C code with and without `volatile`. Show how `volatile` forces the compiler to emit `LDR` instructions inside the loop on every single iteration.

### 4.4 Misconception 4: Conflating Priority Preemption with Priority Sub-priority in NVIC
- **Student Error:** Believing that an interrupt with higher sub-priority can interrupt (preempt) a running interrupt with lower sub-priority if both share the same preemption priority.
- **Root Cause:** Misinterpreting the word "priority".
- **Remediation Strategy:** Teach the strict rule: **Only Preemption Priority controls nesting.** Sub-priority is used solely as a tie-breaker when two interrupts trigger simultaneously.

### 4.5 Misconception 5: Sizing I2C Open-Drain Pull-Up Resistors
- **Student Error:** Assuming any generic resistor (e.g., $10\text{ k}\Omega$) works for all I2C bus speeds.
- **Root Cause:** Overlooking bus parasitic capacitance ($C_b$) and RC rise-time dynamics.
- **Remediation Strategy:** Have students measure SCL rise times on an oscilloscope with $1\text{ k}\Omega$, $4.7\text{ k}\Omega$, and $100\text{ k}\Omega$ resistors at $400\text{ kHz}$ Fast-Mode to witness bus signal distortion firsthand.

## 5. Comprehensive Question Bank with Complete Solutions

### Section A: Short Answer Conceptual Questions (15 Questions)

#### Question A1
**Question:** Explain why the Thumb execution bit ($T$-bit) in the EPSR register of the ARM Cortex-M4 processor must always be set to 1. What happens if software attempts to execute an instruction with $T = 0$?  
**Solution:** The Cortex-M4 core executes exclusively Thumb-2 instructions and does not support original 32-bit ARM state instructions. Therefore, bit 24 ($T$-bit) of the Execution Program Status Register (EPSR) must always be 1. If an instruction attempt (or branch instruction `BX`/`BLX` without least-significant bit set to 1) clears the $T$-bit to 0, the core immediately generates a `UsageFault` exception (invalid state fault), which escalates to a `HardFault` if unhandled.

#### Question A2
**Question:** Differentiate between Memory-Mapped I/O and Port-Mapped I/O architectures. Which model does the ARM Cortex-M4 utilize?  
**Solution:**
- **Memory-Mapped I/O:** Peripherals share the unified flat memory address space with SRAM and Flash. Peripheral registers are accessed using standard memory load/store instructions (`LDR`/`STR`).
- **Port-Mapped I/O:** Peripherals reside in a dedicated I/O address space separate from memory, requiring specialized I/O instructions (e.g., `IN` / `OUT` in x86).
- **Cortex-M4:** Uses **Memory-Mapped I/O** across its 4 GB address space.

#### Question A3
**Question:** Define "Interrupt Latency" in real-time embedded systems. State two microarchitectural mechanisms in the ARM Cortex-M4 designed to minimize interrupt latency.  
**Solution:** Interrupt Latency is the time interval elapsed between the assertion of a hardware interrupt signal and the execution of the first instruction of the corresponding Interrupt Service Routine (ISR).  
Two Cortex-M4 mechanisms that minimize latency:
1. **Tail-Chaining:** Reduces back-to-back exception entry latency to 6 clock cycles by skipping unstacking/restacking.
2. **Late Arrival Preemption:** Allows a higher-priority interrupt arriving during hardware stacking of a lower-priority interrupt to be serviced first without re-stacking.

#### Question A4
**Question:** What is the purpose of the `volatile` type qualifier in embedded C programming? Provide a code example where omitting `volatile` causes system failure.  
**Solution:** `volatile` informs the compiler that a variable's value can be modified by hardware external to the current execution thread (e.g., an ISR or hardware peripheral register). It prevents the compiler from optimizing out memory reads or caching the variable in a CPU register.  
*Example:*
```c
volatile uint8_t rx_ready = 0; // Omitting volatile causes compiler to optimize while(1) into an infinite loop
void USART2_IRQHandler(void) { rx_ready = 1; }
int main(void) {
    while(!rx_ready); // Polling loop
}
```

#### Question A5
**Question:** State the Liu & Layland schedulability condition for Rate Monotonic Scheduling (RMS). What is the theoretical utilization limit for a 2-task system?  
**Solution:** A periodic task set of $n$ tasks is guaranteed schedulable under RMS if:
$$U = \sum_{i=1}^n \frac{C_i}{T_i} \le n(2^{1/n}-1)$$
For $n = 2$ tasks:
$$U(2) = 2 \left(2^{1/2} - 1\right) = 2 (\sqrt{2} - 1) = 2 (1.4142 - 1) \approx 0.8284 \ (82.84\%)$$

#### Question A6
**Question:** Explain the structural difference between `MSP` (Main Stack Pointer) and `PSP` (Process Stack Pointer) in the ARM Cortex-M4 architecture.  
**Solution:**
- **MSP (Main Stack Pointer):** Used by default upon reset, and used for all Exception/Interrupt Handlers (Handler Mode) and OS kernel execution.
- **PSP (Process Stack Pointer):** Used exclusively in Thread Mode for user application tasks when enabled by setting `CONTROL.SPSEL = 1`. This isolates OS stack space from application stack overflow risks.

#### Question A7
**Question:** Contrast Static Power Dissipation with Dynamic Power Dissipation in CMOS microcontrollers. How does reducing clock frequency affect each?  
**Solution:**
- **Dynamic Power:** $P_{\text{dynamic}} = \alpha C_L V_{DD}^2 f_{\text{clk}}$, caused by capacitive charging/discharging during transistor switching. Scaling down $f_{\text{clk}}$ reduces dynamic power **linearly**.
- **Static Power:** $P_{\text{static}} = V_{DD} \times I_{\text{leakage}}$, caused by subthreshold leakage current. Clock frequency has **no direct impact** on static power dissipation.

#### Question A8
**Question:** What is an "IT (If-Then) Block" in Thumb-2 assembly? Why is it preferred over conditional branch instructions in pipeline processors?  
**Solution:** An IT block permits up to four subsequent instructions to execute conditionally based on APSR status flags without executing branch instructions. Conditional branches flush the 3-stage CPU pipeline when taken, incurring a multi-cycle branch penalty stall. IT blocks avoid pipeline flushes completely.

#### Question A9
**Question:** Describe the function of the SysTick timer in ARM Cortex-M microcontrollers.  
**Solution:** SysTick is a 24-bit system down-counter integrated directly into the Cortex-M core. It generates periodic time-base interrupts (`SysTick_IRQn`) used by Real-Time Operating Systems (e.g., FreeRTOS) to increment tick counts, manage task delays, and trigger context switches.

#### Question A10
**Question:** What is "Priority Inversion" in RTOS multi-tasking? Name the protocol used to resolve it.  
**Solution:** Priority Inversion is a scenario where a high-priority task is indirectly blocked from executing by a medium-priority task, because a low-priority task holds a shared resource (mutex) needed by the high-priority task. It is resolved using the **Priority Inheritance Protocol**, where the low-priority task temporarily inherits the high-priority task's priority while holding the mutex.

#### Question A11
**Question:** Explain why open-drain configuration with external pull-up resistors is required for the I2C bus SDA and SCL lines.  
**Solution:** Open-drain drivers allow multiple devices on the bus to pull the signal line LOW without causing hardware short-circuit current contention (bus contention). If two devices drive opposite logic levels simultaneously on a push-pull bus, $V_{DD}$ connects directly to GND, damaging IC pins. Open-drain implements a wired-AND logic structure.

#### Question A12
**Question:** What is the role of the `BASEPRI` special-purpose register in Cortex-M4 exception management?  
**Solution:** `BASEPRI` disables (masks) interrupts with a priority level equal to or lower (numerically greater than or equal to) the value set in `BASEPRI`. Interrupts with higher priority (numerically lower) are still allowed to execute. Setting `BASEPRI = 0` disables masking.

#### Question A13
**Question:** Differentiate between Binary Semaphores and Mutexes in FreeRTOS.  
**Solution:**
- **Binary Semaphore:** Used primarily for **synchronization** (one task/ISR signals another). It has no ownership concept and does not implement priority inheritance.
- **Mutex:** Used for **mutual exclusion** (protecting shared resources). It possesses a concept of ownership (the task that takes it must give it back) and implements Priority Inheritance to prevent priority inversion.

#### Question A14
**Question:** In SAR ADCs, explain the trade-off between Sampling Time ($t_{\text{sample}}$) and Source Input Impedance ($R_S$).  
**Solution:** The ADC sampling capacitor $C_{\text{sample}}$ must charge to within 0.5 LSB of the input voltage during $t_{\text{sample}}$. High input source impedance $R_S$ increases the RC charging time constant ($\tau = (R_S + R_{\text{switch}}) C_{\text{sample}}$), requiring a longer configured $t_{\text{sample}}$ to prevent conversion inaccuracy.

#### Question A15
**Question:** Explain the difference between Equivalence Partitioning and Boundary Value Analysis (BVA) in software unit testing.  
**Solution:**
- **Equivalence Partitioning:** Divides the input domain into classes of valid and invalid data, selecting one representative test case per partition.
- **Boundary Value Analysis:** Focuses explicitly on the edges of these partitions, selecting test cases at the extreme boundaries ($\text{Min}-1, \text{Min}, \text{Min}+1, \text{Max}-1, \text{Max}, \text{Max}+1$) where software defects statistically concentrate.

#### Design Problem C1: Dual-Task FreeRTOS Data Logger System
**Requirement:** Design a complete C FreeRTOS application for an ARM Cortex-M4 microcontroller.
- **Task A (`Task_SensorAcquire`, Priority 2):** Periodically triggered every $50 \text{ ms}$, reads 12-bit ADC values, writes to a shared circular buffer protected by a Mutex (`xMutexBuffer`).
- **Task B (`Task_UARTTransmit`, Priority 1):** Reads samples from the circular buffer and transmits them over UART when buffer contains data.
- Include proper FreeRTOS initialization, task creation, and Mutex handling code.

**Solution:**
```c
#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"
#include <stdint.h>

#define BUFFER_SIZE 64
typedef struct {
    uint16_t data[BUFFER_SIZE];
    uint16_t head;
    uint16_t tail;
    uint16_t count;
} CircularBuffer_t;

CircularBuffer_t sensorBuf = {0};
SemaphoreHandle_t xMutexBuffer;

void Buffer_Put(uint16_t val) {
    if (sensorBuf.count < BUFFER_SIZE) {
        sensorBuf.data[sensorBuf.head] = val;
        sensorBuf.head = (sensorBuf.head + 1) % BUFFER_SIZE;
        sensorBuf.count++;
    }
}

uint8_t Buffer_Get(uint16_t *val) {
    if (sensorBuf.count > 0) {
        *val = sensorBuf.data[sensorBuf.tail];
        sensorBuf.tail = (sensorBuf.tail + 1) % BUFFER_SIZE;
        sensorBuf.count--;
        return 1;
    }
    return 0;
}

void Task_SensorAcquire(void *pvParameters) {
    TickType_t xLastWakeTime = xTaskGetTickCount();
    uint16_t adc_val = 0;
    
    for (;;) {
        // Mock ADC Read
        adc_val = (uint16_t)(*(volatile uint32_t*)0x4001204C); // ADC1_DR
        
        if (xSemaphoreTake(xMutexBuffer, portMAX_DELAY) == pdTRUE) {
            Buffer_Put(adc_val);
            xSemaphoreGive(xMutexBuffer);
        }
        vTaskDelayUntil(&xLastWakeTime, pdMS_TO_TICKS(50));
    }
}

void Task_UARTTransmit(void *pvParameters) {
    uint16_t data_to_send;
    for (;;) {
        if (xSemaphoreTake(xMutexBuffer, portMAX_DELAY) == pdTRUE) {
            if (Buffer_Get(&data_to_send)) {
                // Transmit over UART
                while (!(*(volatile uint32_t*)0x40004400 & (1U << 7))); // TXE
                *(volatile uint32_t*)0x40004404 = (uint8_t)(data_to_send & 0xFF);
            }
            xSemaphoreGive(xMutexBuffer);
        }
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

int main(void) {
    xMutexBuffer = xSemaphoreCreateMutex();
    if (xMutexBuffer != NULL) {
        xTaskCreate(Task_SensorAcquire, "Acquire", 256, NULL, 2, NULL);
        xTaskCreate(Task_UARTTransmit,  "Transmit", 256, NULL, 1, NULL);
        vTaskStartScheduler();
    }
    while (1);
}
```

**Requirement:** Write a zero-dependency register-level C function `PWM_Init_PA0(uint32_t frequency_hz, uint8_t duty_percent)` that configures PA0 as `TIM2_CH1` PWM output at $16 \text{ MHz}$ system clock frequency.

    // 1. Enable Clocks: GPIOA (Bit 0) and TIM2 (Bit 0)
    *(volatile uint32_t*)0x40023830 |= (1U << 0);  // RCC_AHB1ENR
    *(volatile uint32_t*)0x40023840 |= (1U << 0);  // RCC_APB1ENR

    *(volatile uint32_t*)0x40020020 &= ~(0xFU << 0); // AFRL register
    *(volatile uint32_t*)0x40020020 |=  (1U   << 0);

    uint32_t sys_clk = 16000000U;

    *(volatile uint32_t*)0x40000000 |= (1U << 0); // TIM2_CR1 (CEN)

#### Design Problem C3: Thumb-2 Assembly Array Summation with IT Block
**Requirement:** Write a Thumb-2 assembly subroutine `uint32_t Sum_Filter(const int32_t *array, uint32_t length)` that iterates through an array of signed 32-bit integers, accumulates positive values into R0, and ignores negative values using an IT conditional block.

**Solution:**
```assembly
    .syntax unified
    .cpu cortex-m4
    .thumb
    .global Sum_Filter
    .type Sum_Filter, %function

Sum_Filter:
    PUSH    {R4, LR}            ; Save R4 and Link Register
    MOV     R2, #0              ; R2 = Accumulator (Sum = 0)
    
Loop_Start:
    CBZ     R1, Loop_End        ; If length (R1) == 0, exit loop
    
    LDR     R3, [R0], #4        ; Load *array into R3, post-increment pointer by 4
    CMP     R3, #0              ; Compare array element with 0
    
    IT      GT                  ; If Greater Than (R3 > 0)
    ADDGT   R2, R2, R3          ; (T) Add R3 to Accumulator R2
    
    SUBS    R1, R1, #1          ; Decrement length count
    B       Loop_Start          ; Branch to loop start

Loop_End:
    MOV     R0, R2              ; Move final sum into return register R0
    POP     {R4, PC}            ; Return from subroutine
```

#### Design Problem C4: I2C Bit-Bang Master Driver in C
**Requirement:** Write low-level C functions for I2C START condition, Bit-Write, and STOP condition using direct GPIO pin manipulation for SDA (PC1) and SCL (PC0).

**Solution:**
```c
#include <stdint.h>

#define GPIOC_ODR (*(volatile uint32_t*)0x40020814)
#define GPIOC_IDR (*(volatile uint32_t*)0x40020810)

void Delay_us(uint32_t us) {
    for (volatile uint32_t i = 0; i < us * 10; i++);
}

void I2C_SDA_High(void) { GPIOC_ODR |= (1U << 1); }
void I2C_SDA_Low(void)  { GPIOC_ODR &= ~(1U << 1); }
void I2C_SCL_High(void) { GPIOC_ODR |= (1U << 0); }
void I2C_SCL_Low(void)  { GPIOC_ODR &= ~(1U << 0); }

void I2C_Start(void) {
    I2C_SDA_High();
    I2C_SCL_High();
    Delay_us(5);
    I2C_SDA_Low();  // High-to-Low transition on SDA while SCL is High
    Delay_us(5);
    I2C_SCL_Low();
}

void I2C_Stop(void) {
    I2C_SDA_Low();
    I2C_SCL_Low();
    Delay_us(5);
    I2C_SCL_High();
    Delay_us(5);
    I2C_SDA_High(); // Low-to-High transition on SDA while SCL is High
    Delay_us(5);
}

uint8_t I2C_WriteByte(uint8_t data) {
    for (uint8_t i = 0; i < 8; i++) {
        if (data & 0x80) I2C_SDA_High();
        else             I2C_SDA_Low();
        data <<= 1;
        Delay_us(2);
        I2C_SCL_High();
        Delay_us(5);
        I2C_SCL_Low();
    }
    // Read ACK/NACK bit
    I2C_SDA_High(); // Release SDA line
    I2C_SCL_High();
    Delay_us(2);
    uint8_t ack = !(GPIOC_IDR & (1U << 1)); // 0 = ACK, 1 = NACK
    I2C_SCL_Low();
    return ack;
}
```

#### Design Problem C5: Hardware Watchdog & DMA ADC System Integration
**Requirement:** Formulate an architectural block diagram and pseudo-code integration routine for a safety-critical motor controller using an STM32 Cortex-M4. The system must continuously sample motor current via 12-bit ADC with DMA into RAM, inspect for overcurrent, service the Window Watchdog Timer (WWDG), and enter Standby Mode upon emergency shutdown.

**Architectural Diagram & Solution:**
```
+-----------------------------------------------------------------------------------+
|                        SAFETY-CRITICAL SYSTEM ARCHITECTURE                        |
|                                                                                   |
|  +--------------------+    DMA1    +---------------------+    ADC Interrupt       |
|  | ADC1 Channel 0     |───────────►| SRAM Buffer         |─────────────────────┐ |
|  | (Current Sensor)   |            | (Circ. DMA Buffer)  |                     │ |
|  +--------------------+            +---------------------+                     ▼ |
|                                                                    +--------------------+
|  +--------------------+                                            | Overcurrent Check  |
|  | WWDG Watchdog      |◄────────── Refresh Feed ───────────────────| Safety Task        |
|  | (Hardware Guard)   |                                            +----------┬---------+
|  +--------------------+                                                       │         |
|                                                                     Emergency │ Trigger |
|                                                                               ▼         |
|                                                                    +--------------------+
|                                                                    | Standby Power Mode |
|                                                                    | (Emergency Halt)   |
|                                                                    +--------------------+
+-----------------------------------------------------------------------------------+
```

```c
#include <stdint.h>

#define OVERCURRENT_THRESHOLD 3500 // ~2.8V on 12-bit ADC
volatile uint16_t adc_dma_buffer[100];

void System_Safety_Check(void) {
    uint32_t sum = 0;
    for (int i = 0; i < 100; i++) {
        sum += adc_dma_buffer[i];
    }
    uint16_t avg_current = sum / 100;

    if (avg_current > OVERCURRENT_THRESHOLD) {
        // Disable PWM Motor Driver Immediately
        *(volatile uint32_t*)0x40000000 &= ~(1U << 0); // TIM2 CEN = 0
        
        // Enter Low Power Standby Mode (Shutdown)
        *(volatile uint32_t*)0x40007000 |= (1U << 1);  // PWR_CR PDDS bit
        *(volatile uint32_t*)0xE000ED10 |= (1U << 2);  // Core SCB SCR SLEEPDEEP
        __asm volatile ("wfi");                        // Wait For Interrupt / Standby
    } else {
        // Feed Hardware Window Watchdog (WWDG) to prevent system reset
        *(volatile uint32_t*)0x40002C00 = 0x7F; // Refresh WWDG Counter
    }
}
```
